# 系统设置移植 - 群聊视觉上下文与多模态转述 (astrbot_plugin_sys_setting_port)

这是一个为 AstrBot 提供会话请求超时保护、群聊上下文感知、图片转述、自定义艾特等待和私聊主动回复的插件。

## 🌟 核心功能

AstrBot 的图片处理和群聊上下文感知分别由不同链路负责。本插件在 LLM 请求时从 NapCat 获取当前群真实最新消息，并把时间线作为不保存的临时内容注入当前请求；群消息正文不会常驻插件内存。

本插件提供以下高级特性：

1. **真实最新群聊上下文**：Bot 被唤醒时通过 NapCat `get_group_msg_history` 获取当前群真实最新 X 条消息，按原始时间顺序解析普通文字、At、引用、表情和图片；插件重启不会导致此前群消息消失。
2. **“阅后即焚”注入**：即时获取的群聊时间线以独立临时上下文消息注入，并通过 `_no_save` 标记阻止 AstrBot 写入会话历史。请求完成后不在插件内存保存群消息正文。
3. **静默图片持久感知**：图片白名单群收到图片时，即使未唤醒主聊天 AI，也会生成描述并写入 SQLite。请求时按群号和消息 ID 复用描述；默认每群最多 100 条图片消息、8 小时过期，设置为 0 可永不过期。
4. **智能转述判定官**：引入可选的判定模型（如 Gemini Flash 或 GPT-4o-mini），精准识别转述模型返回的“变相拒绝”或“虚假描述”。若判定不通过，将自动触发重试。
5. **硬核报错重试**：自动捕获 403、429、超时等所有底层 API 异常并触发重试，不再依赖脆弱的关键词匹配。
6. **结构化转述提取**：强制转述模型使用 `<caption_result>` 标签，实现描述内容的精准提取，有效隔离模型废话。
7. **多模态直通与插件兼容**：引用图片默认只发送已有描述；当前消息命中“仔细看”“看原图”等关键词时，多模态模型只接收原图与来源。图生图等插件仍可获取引用原图。纯文本模型匹配会综合请求模型名、Provider 实际模型名、配置模型名和 Provider ID。
8. **私聊转述持久化**：私聊中的图片转述结果作为普通用户消息内容保存到会话历史；群聊转述仍只参与当前请求。用于生成描述的转述提示词本身不会写入主会话。
9. **会话隔离超时看门狗**：单条请求取得会话锁并进入 LLM 请求阶段后开始绝对计时；到期只取消当前消息的 pipeline task，让 AstrBot 在取消传播后释放该会话锁。同会话下一条消息随即继续，其他会话始终独立运行。
10. **私聊主动回复 (AGI 进化版)**：当私聊闲置时，机器人会主动找用户聊天。支持“纯随机”与“智能判定”双模式，具备硬盘级持久化状态。
11. **自定义等待机制 (增强版)**：接管系统原有的「只 @ 机器人」等待逻辑，支持自定义等待时间、回复词及完美超时唤醒（正确引用原消息）。

## ⚙️ 配置说明

请在 AstrBot 的 WebUI 后台 -> 插件管理 -> `astrbot_plugin_sys_setting_port` 中进行配置：

### ⏱️ 会话请求超时配置
- **启用会话请求超时看门狗**：默认开启；关闭后不注册请求计时任务。
- **单次会话请求绝对超时**：默认 `180` 秒，可按需要设置为 `120` 秒。计时从该请求取得会话锁并进入 LLM 请求 hook 后开始，不包含此前等待同会话锁的排队时间。
- **请求超时后发送提示**：决定强制终止后是否向原会话发送提示。
- **请求超时提示文本**：可自定义提示内容；留空则不发送。
- 启动时日志包含 `【会话请求看门狗｜已启动】`；到期取消时包含 `【会话请求超时｜强制终止】`，并记录会话、请求 token、时限和实际耗时。

### 👥 群聊视觉上下文配置
- **启用插件群聊上下文**：启用后由本插件替代 AstrBot 原生群聊上下文感知；当前即时历史仅支持 aiocqhttp/NapCat。
- **每次获取最新群消息数**：每次 LLM 请求从 NapCat 获取的真实最新消息数量，默认 80；只在当前请求内存在。
- **群聊图片理解白名单**：仅列表中的群号会在图片静默到达时调用视觉模型。
- **群聊图片理解模型**：用于生成可复用图片描述的视觉模型。
- **每群图片消息缓存上限**：默认 100；一条多图消息只计一条，按群独立淘汰最旧记录。
- **图片描述过期时间**：默认 8 小时；设置为 0 时永不过期。描述保存在 `data/plugin_data/astrbot_plugin_sys_setting_port/group_image_captions.db`，不会整体载入内存。

### 🖼️ 多模态转述配置
- **多模态转述模型**：选择用于看图的主力模型。
- **启用智能转述判定**：开启后调用判定模型审核转述质量。
- **转述判定模型 / 提示词**：用于执行判定的轻量级模型及指令。
- **启用结构化转述输出**：强制要求模型使用标签包裹描述内容。
- **需要转述的模型列表**：填入需要被转述的纯文本模型名称（支持模糊匹配）。

## 📝 更新日志

### v2.2.0
- **即时真实历史**：群聊上下文改为 LLM 请求时调用 NapCat `get_group_msg_history`，插件重启后仍可取得此前真实最新消息。
- **移除常驻群记录**：删除内存中的 `group_visual_history`、群锁和图片对象缓存，不再让每个经过的群长期占用一组消息列表。
- **静默图片持久化**：图片白名单群仍在适配器消息阶段理解图片，但描述写入按群隔离的 SQLite，不触发主聊天 LLM。
- **容量与过期**：默认每群保留 100 条图片消息描述、8 小时过期；一条多图消息只计一条，过期时间为 0 时永不过期。
- **请求级内存**：NapCat 返回的最新消息只在当前请求格式化和注入，请求结束后释放；群聊时间线仍使用 `_no_save`，不写入 LLM 会话历史。

### v2.1.5
- **修复当前图片不可见**：文本聊天模型命中转述后，群聊描述不再写入 `system_prompt`，而是在全部 LLM hook 完成后以 `_no_save` 临时 user context 最终注入。
- **修复引用图片丢失**：引用图片无既有缓存时会由配置的多模态转述模型重新理解，不再提前从待转述图片列表移除。
- **图片来源分流**：当前消息图片与引用图片分别转述和标注；混合发送时不会再把当前图片误标为引用发送者的图片。
- **防历史膨胀**：群聊图片描述仅参与当前请求并在历史保存阶段跳过；私聊转述仍按原设计持久化。
- **日志增强**：转述日志增加 `kind=current`、`kind=quoted_uncached`、`kind=quoted_cached` 与 `【图片转述｜最终注入】`，可直接确认实际链路。

### v2.1.4
- **新增**：增加按 `unified_msg_origin` 隔离的单请求绝对超时看门狗，默认时限为 180 秒。
- **精准取消**：超时只取消当前消息对应的 pipeline task，不批量终止 Provider 或其他会话任务；`CancelledError` 传播退出会话锁上下文后，同会话下一条请求即可继续。
- **安全清理**：正常完成会取消看门狗；超时、插件卸载和陈旧 token 均有独立清理与防误杀保护。
- **提示与日志**：支持配置超时提示开关和文本，并增加看门狗启动、强制终止醒目日志。

### v2.1.3
- **修复**：将图片转述与群聊上下文拆分为两个 LLM hook；图片转述恢复旧版默认优先级，群聊时间线继续以最低优先级最终注入。
- **修复**：目标模型匹配同时检查 `req.model`、Provider 实际模型名、Provider 配置模型名和 Provider ID，并规范化关键词空格与大小写。
- **持久化**：私聊图片转述结果恢复为普通 `extra_user_content_parts`，随本轮用户消息永久保存；群聊图片转述保持临时。
- **日志**：新增 `【图片转述｜触发】`、`【图片转述｜成功】`、`【图片转述｜主模型失败】`、`【图片转述｜失败】` 醒目标记，显示匹配关键词、当前模型候选、转述 Provider、图片数和注入模式。

### v2.1.2
- **修复**：将 LLM 请求钩子调整为最低优先级，在持久历史等插件完成 `req.contexts` 重建后再执行最终注入。
- **根因**：此前本插件以最高优先级先注入，随后 `astrbot_plugin_persistent_history` 会清空并整体替换 contexts，导致群聊时间线在最终请求前丢失。
- **诊断**：成功日志增加临时上下文在最终 contexts 中的位置；应看到 `群聊上下文已最终注入` 且 `position` 不为 `-1`。

### v2.1.1
- **修复**：群聊上下文改用独立临时上下文消息注入，解决部分版本或 Provider 不读取动态 `system_prompt` 的问题。
- **兼容**：无法构建临时消息的旧版 AstrBot 自动回退到 `system_prompt`。
- **可观测性**：注入成功时记录群号、注入模式、消息条数与字符数，便于从日志直接核验。
- **防膨胀**：临时消息使用 `_no_save` 标记，不写入会话历史；增加重复注入保护。

### v2.1.0
- **重构**：将群聊上下文注入点迁移至 `system_prompt`，尝试实现不写入历史的临时注入。
- **新增**：智能转述判定官功能，精准识别并重试 AI 的拒绝或道歉回复。
- **新增**：结构化转述提取逻辑，支持通过标签精准隔离描述内容。
- **优化**：参考 `nova_omni` 逻辑，通过捕获底层 Exception 实现稳健重试。
- **修复**：修正了群聊视觉感知中的参数传递错误。

### v2.0.0
- **新增**：增加完整群聊上下文，图片描述按原位写入感知记录。
- **新增**：描述复用缓存支持 TTL 和容量限制。
- **修复**：引用图片优先复用已有描述，支持多模态模型命中关键词看原图。

## ⚠️ 注意事项

1. **关闭系统转述**：使用本插件前，请务必将 AstrBot 系统设置中的「默认图片转述模型」留空！
2. **关闭系统等待**：若启用「自定义等待机制」，请务必在系统设置中关闭原有的「只 @ 机器人是否触发等待」！
