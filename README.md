# 系统设置移植 - 群聊上下文、角色感知与多模态转述 (astrbot_plugin_sys_setting_port)

这是一个为 AstrBot 提供会话请求超时保护、群聊上下文与角色感知、图片转述、自定义艾特等待和私聊主动回复的插件。

## 🌟 核心功能

AstrBot 的图片处理和群聊上下文感知分别由不同链路负责。本插件在 LLM 请求时从 NapCat 获取当前群真实最新消息，并把时间线作为不保存的临时内容注入当前请求；群消息正文不会常驻插件内存。

本插件提供以下高级特性：

1. **真实最新群聊上下文**：Bot 被唤醒时通过 NapCat `get_group_msg_history` 获取当前群真实最新 X 条消息，按原始时间顺序解析普通文字、At、引用、表情和图片；插件重启不会导致此前群消息消失。
2. **“阅后即焚”注入**：即时获取的群聊时间线以独立临时上下文消息注入，并通过 `_no_save` 标记阻止 AstrBot 写入会话历史。请求完成后不在插件内存保存群消息正文。
3. **图片描述双层索引**：白名单群的静默图片感知、非白名单群的成功引用转述都会写入 SQLite。消息 ID 索引默认保留 24 小时且不设条数上限，用于 NapCat 历史零下载替换；独立 SHA-256 长期库默认全局保留 100000 组，用于跨群、跨月份重复图片免重新转述。
4. **智能转述判定官**：引入可选的判定模型（如 Gemini Flash 或 GPT-4o-mini），精准识别转述模型返回的“变相拒绝”或“虚假描述”。若判定不通过，将自动触发重试。
5. **硬核报错重试**：自动捕获 403、429、超时等所有底层 API 异常并触发重试，不再依赖脆弱的关键词匹配。
6. **结构化转述提取**：强制转述模型使用 `<caption_result>` 标签，实现描述内容的精准提取，有效隔离模型废话。
7. **多模态直通与插件兼容**：引用图片默认只发送已有描述；当前消息命中“仔细看”“看原图”等关键词时，多模态模型只接收原图与来源。图生图等插件仍可获取引用原图。纯文本模型匹配会综合请求模型名、Provider 实际模型名、配置模型名和 Provider ID。
8. **私聊转述持久化**：私聊中的图片转述结果作为普通用户消息内容保存到会话历史；群聊转述仍只参与当前请求。用于生成描述的转述提示词本身不会写入主会话。
9. **持久化群角色感知**：SQLite 仅保存 AstrBot 系统白名单群的群主和管理员。插件启动时同步，此后默认每 7 天同步；每轮以 `_no_save` 上下文提供 Bot 与当前发言人的群身份，不保存普通成员名单。
10. **角色变化主动核验**：LLM 可在聊天提到群主、管理员或权限变化时调用 `sys_refresh_group_roles`。只有 NapCat 返回有效成员列表且恰有一位群主时才事务替换旧快照；异常或空结果不会清空已有数据。
11. **会话隔离滑动看门狗**：请求取得会话锁后开始计时，每轮工具开始和正常结束都刷新完整时限，避免多轮工具累计耗时误杀；主 Agent 最终响应到达即解除。到期只取消长时间无新进展的当前 pipeline task，响应后处理不计时。
12. **私聊主动回复 (AGI 进化版)**：当私聊闲置时，机器人会主动找用户聊天。支持“纯随机”与“智能判定”双模式，具备硬盘级持久化状态。
13. **自定义等待机制 (增强版)**：接管系统原有的「只 @ 机器人」等待逻辑，支持自定义等待时间、回复词及完美超时唤醒（正确引用原消息）。

## ⚙️ 配置说明

请在 AstrBot 的 WebUI 后台 -> 插件管理 -> `astrbot_plugin_sys_setting_port` 中进行配置：

### ⏱️ 会话请求超时配置
- **启用主 Agent 无进展超时看门狗**：默认开启；关闭后不注册请求计时任务。
- **主 Agent 单阶段无进展超时**：默认 `180` 秒。这是滑动窗口而非整段 Agent 总时限；初始 LLM 等待、工具开始和工具正常结束后都会重新获得完整时限。
- **多轮工具持续刷新**：每轮工具都会触发新的计时窗口，多轮调用就多轮刷新；工具自身仍由 AstrBot 原生工具超时保护。工具异常导致结束钩子缺失时，工具开始时的刷新仍保留会话兜底，不会永久停表。
- **最终回答立即解除**：主 Agent 最终响应到达后立即解除；分段、TTS、情绪分析、装饰和发送不计时。
- **请求超时后发送提示**：决定强制终止后是否向原会话发送提示。
- **请求超时提示文本**：可自定义提示内容；留空则不发送。
- 启动日志包含 `【会话请求看门狗｜已启动】`；收到最终响应后包含 `【会话请求看门狗｜已解除】`；到期取消时包含 `【会话请求超时｜强制终止】`。

### 👑 QQ 群角色感知配置
- **启用 QQ 群角色感知**：默认开启，独立于“插件群聊上下文”开关；关闭时不启动同步任务，也不注入角色快照。
- **群角色自动同步周期**：默认 `7` 天。AstrBot 完整启动或单独重载本插件时都会立即同步一次，此后周期同步；首轮未发现可用 QQ 平台或同步失败时，每 5 分钟自动补偿，不会直接等待一周。
- **同步范围**：仅处理 AstrBot 系统会话白名单中的 QQ 群，并与 Bot 实际已加入群列表求交集；多个 aiocqhttp 平台按平台 ID 隔离保存。
- **存储内容**：只保存群主和管理员的 QQ、显示名、角色及更新时间，不保存普通成员名单；不在特权名单中的群成员在当前请求中判定为普通群成员。
- **注入位置**：角色快照作为 `_no_save` 临时用户上下文，位于 NapCat 即时群聊记录之前，让模型先识别身份再阅读聊天时间线；CrossFlow synthetic wake 会明确区分来源请求者与目标群当前发言人。
- **主动刷新工具**：`sys_refresh_group_roles` 只能刷新当前 QQ 群。适合在聊天明确提到权限变更时调用；API 失败、空列表或群主数据异常均保留旧快照。
- **管理员手动同步**：发送 `/同步群角色` 可立即同步全部系统白名单群，并返回白名单数、当前可同步数、成功数和失败数。

### 👥 群聊视觉上下文配置
- **启用插件群聊上下文**：启用后由本插件替代 AstrBot 原生群聊上下文感知；当前即时历史仅支持 aiocqhttp/NapCat。
- **每次获取最新群消息数**：每次 LLM 请求从 NapCat 获取的真实最新消息数量，默认 80；只在当前请求内存在。
- **群聊图片理解白名单**：仅列表中的群号会在图片静默到达时调用视觉模型。
- **群聊图片理解模型**：用于生成可复用图片描述的视觉模型。
- **群聊图片感知 LLM 单次超时**：默认 `120` 秒；每次重试独立计算，和普通多模态转述超时互不影响。
- **消息 ID 图片描述保留时间**：默认 `24` 小时，不设条数上限；设置为 0 时永不过期。用于 NapCat 历史按消息 ID 零下载替换。
- **SHA-256 长期描述库全局上限**：默认 `100000` 组，可自定义；不按时间过期，命中时累计次数。超限按 `hit_count / 存活天数` 评分淘汰。
- **SHA-256 超限批量淘汰组数**：默认 `10000`，可自定义；仅在超过全局上限时触发。
- **图片描述数据库**：保存在 `data/plugin_data/astrbot_plugin_sys_setting_port/group_image_captions.db`，不保存原图文件。

- **群聊图片理解兜底模型**：群聊主视觉模型全部尝试失败后使用，与普通多模态转述兜底模型独立。
- **群聊视觉模型最大尝试次数**：默认每个模型最多调用 `3` 次；主模型失败后，兜底模型再获得完整 `3` 次。

### 🖼️ 多模态转述配置
- **多模态转述模型**：选择用于看图的主力模型。
- **多模态转述 LLM 单次超时**：默认 `90` 秒；主力和兜底转述模型共用此配置，每次重试独立计算。
- **启用智能转述判定**：开启后调用判定模型审核转述质量。
- **转述判定模型 / 提示词**：用于执行判定的轻量级模型及指令。
- **转述质量判定 LLM 单次超时**：默认 `30` 秒；判定超时按本轮转述失败进入既有重试流程。
- **启用结构化转述输出**：强制要求模型使用标签包裹描述内容。
- **需要转述的模型列表**：填入需要被转述的纯文本模型名称（支持模糊匹配）。

- **GIF 三帧兼容模式**：新增共享开关，默认开启；SYS 向群聊视觉、图片转述和多模态主聊天发送 GIF 前，在内存中转换为去重后的首帧/中帧/尾帧 JPEG，避免不支持 GIF 的 Provider 报错。
- **GIF 描述绑定提示**：图片转述进入上下文时统一组装为 `[GIF 动图：实际转述内容；因为只识别了其中三帧，若群友说你看的不完整、看错，或问的问题转述没提到，可以说手机网络不好、动图没加载全等理由]`，提示与对应描述位于同一个块中。
- **缓存保持干净**：消息 ID 和 SHA 描述库新增 `is_gif` 标志，数据库只保存实际转述内容；历史读取和 SHA 复用时动态组装完整 GIF 描述块，旧数据库自动迁移且不丢数据。
- **安全回退**：静态化失败、开关关闭或帧重复时自动回退原图/去重结果；原始 GIF SHA 计算、消息索引和描述复用语义保持不变。

- **白名单启动与周期同步**：插件加载后同步 AstrBot 系统白名单中的已加入群，默认每 7 天复核一次，各群串行请求并短暂间隔。

- **AI 主动刷新**：新增 `sys_refresh_group_roles`，当群聊提到权限变化时可即时核验当前群；CrossFlow synthetic wake 不会把来源请求者误认成目标群发言人。

### v2.2.10

- **兼容回退**：如果请求中没有可替换的原生引用块，保留临时归属上下文作为兼容兜底。

- **重复图片免转述**：群聊静默感知与文本模型转述均以 64KB 分块计算 SHA-256；命中长期描述时直接复用，不再调用多模态 Provider。
- **单图匹配**：单图消息仅在 SHA-256 完全相同时复用单图描述。
- **多图乱序匹配**：两图计算两张；三图及以上只计算前 3 张。当前消息与历史多图组至少有 2 个 SHA-256 重合时复用既有联合描述，不受图片顺序影响；仅重合 1 张不会复用。
- **跨群复用但不泄露来源**：指纹描述可跨会话命中，但复用后仍写入当前群、当前消息的原有描述表；群聊上下文只显示当前消息及其发送者，不注入来源群、来源消息或来源发送者信息。
- **不保存原图**：SQLite 只保存 SHA-256、联合描述、图片数量、位置、消息标识、命中次数和时间；原图仍由 AstrBot 临时文件机制管理。
- **索引解耦**：消息 ID 描述按独立 TTL 清理；SHA 长期描述不因消息 ID 索引过期而清理。

### v2.2.4
- **恢复引用缓存优先级**：文本聊天模型引用已有描述的图片时，普通询问直接注入 `quoted_cached`，不再无条件重复调用多模态转述 Provider。
- **明确重看才重新转述**：仅当用户消息命中“再看、重看、看原图、看细节”等配置关键词时，绕过既有描述并以 `quoted_reinspect` 重新调用转述 Provider。

### v2.2.3
